# LINE 長輩圖智慧自動回覆機器人 (line-grandma-bot)

[![Version](https://img.shields.io/badge/version-2.6.0-blue.svg)](auto_reply.py)
[![Platform](https://img.shields.io/badge/platform-Windows%2010%20%7C%2011-0078D6.svg)](https://microsoft.com)
[![Python](https://img.shields.io/badge/python-3.10%2B-green.svg)](https://python.org)
[![License](https://img.shields.io/badge/license-MIT-lightgrey.svg)](LICENSE)

專為 Windows LINE 個人電腦版設計的**長輩圖智慧自動回覆守護程式**。  
當長輩或親友傳來長輩圖時，程式會以真人般隨機延遲時間，自動回傳一張**不重複、高畫質的正統台灣長輩圖**；對方傳文字訊息時保持沈默，**維持對話未讀狀態不秒讀**。

---

## 🌟 核心特色

### 1. 獨立「百輪雙向記憶庫」
* 為每位監控好友維護各自獨立的雙向歷史紀錄（預設 100 輪）。
* **保證 100 輪內絕不重複發送同一張圖**給該對象。
* **絕不回送對方曾傳來過的圖片**給對方（防失禮尷尬機制）。

### 2. 跨好友「借花獻佛」大循環
* 好友 A 傳來的正統長輩圖，在 A 的百輪記憶中被封印（不回發給 A）。
* 系統會自動將該圖收納進中央圖庫，日後「借花獻佛」流通發送給好友 B 或好友 C。

### 3. Windows 原生 OCR 真偽鑑別（非長輩圖不收）
* 整合 Windows 10/11 內建繁體中文 OCR 引擎（`Windows.Media.Ocr`）。
* 自動辨識並核對「早安、平安、喜樂、祝福、健康、美好」等核心問候關鍵字。
* 若對方傳送的是生活隨拍照、寵物照、發票或收據，自動拒絕入庫，確保圖庫血統純正。

### 4. 台塑貼圖酷官方圖庫爬蟲（杜絕雜圖）
* 連線台灣 Formosa「台塑貼圖酷」官方長輩圖專案，精準收錄上千幅高解析度每日問候與插畫。
* 具備連線熔斷保護、MD5 指紋去重、單檔 8MB 記憶體上限防護。
* 支援 7 天 TTL 自動過期清理與發送後自動補新圖機制。

### 5. 高 DPI 縮放校正與穩定性防護
* 啟用 Windows 原生 Per-Monitor V2 DPI 感知（`SetProcessDpiAwareness`），徹底解決筆電 125%/150% 螢幕縮放時的滑鼠座標漂移問題。
* 全面採用 `tempfile` + `os.replace` 原子寫入（Atomic Write），杜絕斷電或當機導致 JSON 資料檔損毀。
* 全域例外捕獲與自動退避復原，滑鼠甩至角落觸發防護時守護程式永不閃退中斷。

### 6. 背景動態名單熱更新（Hot Reload）
* 守護程式在背景執行期間，手動修改 `config.json` 新增或移除好友名單，**秒級自動生效**，無需手動重啟程式。

## 🚀 快速開始

### 1. 系統需求
* 作業系統：Windows 10 / Windows 11 (64 位元)
* Python 版本：Python 3.10 或以上（建議 Python 3.12+）
* 電腦版 LINE：保持登入並正常運作

### 2. 標準操作流程 (SOP)
為確保自動化運作 100% 穩定且絕不干擾其他對話，建議採用以下極簡標準流程：
1. **開啟目標獨立聊天室**：在 LINE 電腦版的好友清單中，對 `config.json` 內設定的目標好友（例如「媽媽」）連點兩下開啟**獨立聊天室視窗**（直接最小化至工作列即可）。
2. **零設定全自動守護 (Zero-Config)**：直接啟動 `run_auto_reply.bat`。程式具備動態頻道自動學習技術，當目標好友傳來長輩圖或貼圖時，背景全自動完成頻道綁定與回覆，**完全無需任何手動校準指令**。
3. **安全回覆與自動最小化**：程式喚醒視窗、驗證視窗身分與訊息方向後貼圖送出，並自動重新最小化維持未讀狀態，完全不干擾您在 LINE 主視窗與其他親友交談。
> **初次綁定需保持視窗可見**：尚未綁定的頻道要靠聊天視窗的異動來比對，最小化的視窗讀不到指紋，程式為避免搶奪焦點也不會自動彈出視窗，日誌會顯示「視窗處於最小化狀態」。若視窗在 15 秒內仍未還原，該張圖會被略過、不補回覆。請先還原並保持視窗可見，等第一張圖綁定成功後即可最小化。

### 3. 安裝相依套件
在專案根目錄開啟 PowerShell，執行：
```powershell
pip install -r requirements.txt
```

### 4. 設定監控名單
首次使用時，請複製 `config.example.json` 為 `config.json`：
```powershell
copy config.example.json config.json
```
使用任何文字編輯器開啟 `config.json`，在 `targets` 陣列填入欲監控回覆的好友 LINE 顯示名稱：
```json
{
  "targets": [
    "媽媽",
    "爸爸",
    "大舅舅"
  ],
  "images_dir": "images",
  "trigger_mode": "photo_and_sticker",
  "min_delay_seconds": 5,
  "max_delay_seconds": 900,
  "cooldown_seconds": 30,
  "history_rounds": 100,
  "replace_after_send": true,
  "collect_incoming_images": true,
  "image_ttl_days": 7,
  "min_image_pool": 10,
  "auto_crawl_images": true,
  "close_window_after_send": true,
  "time_aware_images": true,
  "stop_command": "結束長輩圖機器人",
  "stop_command_chats": [],
  "notify_log": false,
  "notify_monthly_cap": 150
}
```

#### ⚙️ 設定參數詳解
| 參數名稱 | 預設值 | 說明 |
| :--- | :---: | :--- |
| `targets` | `["媽媽"]` | 監控回覆的好友名稱陣列（支援多位好友，需與 LINE 上顯示名稱完全相符）。 |
| `images_dir` | `"images"` | 長輩圖存放資料夾路徑。 |
| `trigger_mode` | `"photo_and_sticker"` | 回覆觸發模式：`"photo_and_sticker"`（預設，對方發照片或貼圖時回覆長輩圖；對方傳純文字時保持沉默維持未讀）；`"photo_only"`（僅限對方傳照片時回覆）；`"all"`（文字、貼圖與照片皆回覆）。 |
| `min_delay_seconds` | `5` | 模擬真人延遲回覆**最短秒數**。 |
| `max_delay_seconds` | `900` | 模擬真人延遲回覆**最長秒數**（預設 900 秒 = 15 分鐘，每次會在此區間內隨機擲出秒數）。等待期間監聽暫停（日誌每分鐘倒數），此時其他聊天室的新圖不會被處理，且未綁定頻道的自動綁定可能因時間差過大被拒；等待結束後仍會重新核驗視窗、前景與方向，並重驗時段。 |
| `cooldown_seconds` | `30` | 防洗版全域冷卻安全間隔（秒）。 |
| `history_rounds` | `100` | 每位好友獨立記憶輪數（100 輪內不發送相同圖片，也不把對方曾傳給你的圖片回傳）。 |
| `collect_incoming_images` | `true` | 是否透過原生 OCR 自動辨識並收納對方傳來的長輩圖進入圖庫（借花獻佛）。 |
| `replace_after_send` | `true` | 圖片送出後是否立即從本機淘汰，並自動從網路抓取全新長輩圖遞補。 |
| `image_ttl_days` | `7` | 網路抓取的長輩圖保存期限（天），過期自動清理換新以保持圖庫新鮮。 |
| `min_image_pool` | `10` | 圖庫最低儲備數量，低於此數量時自動連網補充。 |
| `auto_crawl_images` | `true` | 是否允許圖庫不足時自動連網下載補充。 |
| `close_window_after_send` | `true` | 發送完成後是否自動將對話框最小化至工作列，維持後續未讀狀態。 |
| `stop_command` | `"結束長輩圖機器人"` | 停止指令的文字。你在 `stop_command_chats` 內的聊天室自己發了含此文字的訊息，程式立即結束。比對時忽略空白與標點，OCR 認錯一字也算（例如「結束長輩圖機器八」）。 |
| `stop_command_chats` | `[]` | 接受你下停止指令的聊天室名單，名稱需與 LINE 顯示名稱完全相符（例如官方帳號 `Notify Bot`）；空白代表停用此功能。只認「你自己發」的訊息，對方傳來的不算；聊天室需開成獨立視窗並保持展開（不能最小化）。 |
| `notify_log` | `false` | 把啟動、回覆、停止與警告/錯誤推播到 LINE 官方帳號（例如 `Notify Bot`），在聊天室裡看程式的狀況。需要先建立憑證檔，見下方「Notify Bot 推播」。修改後即時生效。 |
| `notify_monthly_cap` | `150` | 每月最多推播則數。官方帳號免費方案每月上限 200 則（整個帳號共用），預設留 50 則給手動測試。達到上限後只記在本機，下個月恢復。 |
| `time_aware_images` | `true` | 依時段挑圖：05-11 時只送早安或無時段字樣的圖，11-17 時送午安，17-05 時送晚安。以 OCR 辨識圖上字樣並快取於 `image_tags.json`；沒有該時段的圖時，改用已標記為 `neutral`（無時段字樣）的圖代替；兩者皆無才不發送。OCR 找不到問候語的圖視為未知，不會被挑選，請用 `--tag-image` 手動標記。 |

## 💻 常用執行指令

### 一鍵啟動（最推薦）
直接雙擊執行目錄下的 **`run_auto_reply.bat`** 即可在背景常駐監聽。

### 命令列常用指令
```powershell
# 1. 啟動常駐自動回覆監聽 (圖庫不足會自動連網補圖)
python auto_reply.py

# 2. 查看目前程式版本號
python auto_reply.py --version

# 3. 馬上連網抓取 20 張正統長輩圖進圖庫備用
python auto_reply.py --crawl 20

# 4. 手動測試發送一次給指定聯絡人 (驗證發送流程與最小化動作)
python auto_reply.py --test "媽媽"

# 5. 精確校準指定好友的快取頻道 (例如: --calibrate "媽媽")
python auto_reply.py --calibrate "媽媽"

# 6. 查看現有圖庫清單與每張圖在各位好友百輪記憶庫中的使用狀態
python auto_reply.py --list-images

# 7. 掃描目前桌面上所有 LINE 視窗控制代碼與標題
python auto_reply.py --scan-windows

# 8. 清空所有聯絡人的百輪歷史記憶
python auto_reply.py --clear-history

# 9. 不傳送也不接收訊息的手動綁定 (名稱須已在 targets 內；Hash 前綴至少 8 碼，且只能對應 1 個快取資料夾)
python auto_reply.py --bind "媽媽" db680a8a

# 9-1. 最簡單的綁定 (請先關閉常駐程式，避免舊圖寫入被當成新圖)：執行後 30 秒內，在 LINE 開啟該好友聊天室並點開任一張舊圖片 (其他聊天室請勿操作)，程式自動辨識並綁定
python auto_reply.py --bind-view "媽媽"

# 9-2. 補圖到指定張數 (預設 30)，已標記為 neutral 的圖先計入總數，其餘名額由早安、午安、晚安平均分配
python auto_reply.py --fill-pool 30

# 9-3. 手動標記圖片時段 (morning / noon / evening / neutral)，標記 neutral 的圖任何時段皆可使用
python auto_reply.py --tag-image grandma_xxx.jpg neutral

# 10. 解除綁定 (可用名稱或 Hash 前綴)
python auto_reply.py --unbind "媽媽"
```

### Notify Bot 推播

把程式的重要事件推到你的 LINE，不用一直看電腦。需要一個 LINE 官方帳號（Messaging API），並先加為好友：

1. 在 `~/.line-notify.env`（可用環境變數 `LINE_NOTIFY_ENV` 指定路徑；找不到時改讀 `~/.line-test.env`）寫入：
   ```
   LINE_TOKEN=<Channel access token (long-lived)>
   LINE_USER_ID=<你的 User ID，U 開頭>
   ```
2. `config.json` 設 `"notify_log": true`。
3. 推播的內容：
   - 🟢 啟動（版本、監控名單、停止指令聊天室）
   - 📨 每次回覆長輩圖（對象與檔名）
   - 🔴 停止（Ctrl+C 或停止指令）
   - ⚠️ 警告與錯誤：`[安全隔離]`、`[警告]`、`[錯誤]`、`[例外防護]` 開頭的 log，以及 logging 的 WARNING 以上。同一類 30 分鐘最多推一次，全部每小時最多 6 則。完整 log 仍在本機。
4. 額度保護：本機用 `notify_state.json` 記本月用量，每次啟動後第一次推播會向 LINE 查實際用量（手動測試用掉的也算），達到 `notify_monthly_cap` 就不再推；LINE 回 429 也視為本月用完。推播在背景執行，網路慢或失敗不會影響監聽，只在本機印出「[通知]」提示。

**注意**：如果推播的聊天室同時在 `targets` 裡，且 `trigger_mode` 為 `all`，推來的文字會被當成對方訊息而觸發回覆；請用預設的 `photo_and_sticker`。

## 📝 版本異動紀錄 (Changelog)

### [v2.6.0] - 2026-10-31
#### 停止指令改成「你自己在聊天室發」
- **改動（不相容）**：停止指令不再看好友傳來的訊息，改成你自己在 `stop_command_chats` 內的聊天室，用自己的帳號發含 `stop_command` 的文字。好友傳來的指令不再生效；設定檔的欄位名稱與格式不變，但意義改了，請確認名單內是你要下指令的聊天室（例如 `Notify Bot`）。
- **運作方式**：自己發的訊息不會產生未讀數，所以靠訊息列表簽章偵測變化。只在聊天室視窗已在前景（你正在打字）、列表有變化、且最底部是你自己發的文字氣泡時，才用 OCR 讀右側氣泡內容，讀法與先前相同（3 種前處理任一讀到就停，都讀不到字時不停止）。檢查不再把視窗切到前景，也不再替你縮小視窗，所以不會再和回圖流程搶視窗。
- **限制**：聊天室視窗縮小或沒開時你不可能在裡面打字，所以不檢查。啟動後若聊天室最底部還留著上一次的停止指令，之後視窗簽章變化（例如調整視窗大小）時會被當成新指令再次停止；先在聊天室發任何一則訊息，或刪除那則指令即可。官方帳號推來的訊息（最底部在左側）不會被當成指令。
- **內部整理**：移除好友路徑相關的未讀數檢查與左側文字 OCR（`last_left_message_has_text`）；`_left_message_blocks` 新增 `side` 參數，右側取樣帶為距右緣 24px 往左 160px。

#### 窄視窗下左右判斷出錯
- **修正**：聊天視窗很窄時，最底部訊息在左側也會被判成「自己發的」（實測：視窗 390 邏輯像素寬時誤判，最大化後正確）。這會讓「自循環保護」誤攔本該送出的長輩圖，也會影響送出後的送達驗證。現在 `is_last_message_from_self_in_chat` 與 `verify_message_sent_to_chat` 在視窗邏輯寬度小於 800px 時，先暫時最大化、判斷完還原（已最大化、最小化或讀不到視窗狀態時不動視窗）。
- **停止指令**：改成先 OCR 看有沒有指令，讀到才最大化確認它是聊天室最後一則（避免上方留著舊指令、下面已有新訊息時誤停），平常在聊天室打字不會動你的視窗。

#### 開發中（已簽入，尚未驗證完成）
- **圖庫來源可設定**：`crawl_images.py` 新增 `image_sources`（網址範本含 `{n}`、`start`~`end` 編號範圍、選填 `category` 與 `pad`）。空白使用預設的 Formosa 貼圖酷每日問候攝影與插畫。節慶類是特定節日的圖、`note-short` 是短影片，所以沒有收進預設。
- **識別長輩圖才回覆**：新增 `require_grandma_image`（預設 `true`）。對方傳來的圖要通過識別才回覆；貼圖、生活照、讀不出字的、只傳文字的都不理會（回傳 `SKIPPED_NOT_GRANDMA`，不啟動冷卻也不重試，並記下對方傳過這張圖）。識別方式：快取檔 Pillow 打得開時直接 OCR 檔案（邊長至少 250px）；LINE 電腦版實際的快取檔是**加密的 `.eimg`，打不開**，所以改成截聊天視窗裡那張圖的縮圖做 OCR（內容寬度小於 200 邏輯像素視為貼圖）。截圖只在視窗已是前景時進行（否則可能截到別的視窗），視窗不在前景就延到實際要回覆、視窗被帶到前景後再判斷，判斷不出來走既有的重試流程。OCR 是用多種前處理（原圖、灰階拉對比、反相、二值化）任一種讀到長輩圖關鍵字就算。已用真機驗證：真的長輩圖放行並回覆、生活照與貼圖不回覆。另外，原本「訊息類型核驗」在剛還原視窗時常因 LINE 還沒重繪而判斷不出來，現在會稍等再試（最多 3 次）。
- **無時段圖自動替代**：新增 `auto_neutral_images`（**預設 `false`**）。實測 30 張隨機圖只有 2 張讀得到問候語，OCR 沒讀到問候語絕大多數是辨識失敗，不是真的無時段，所以先不開；比較可靠的路是「來源本身標明時段」（`image_sources` 的 `category`）。細節見下一版的規劃。

#### Notify Bot 推播
- **新增**：`notify_log` 開啟後，啟動、回覆、停止與警告/錯誤會推播到 LINE 官方帳號（新增 `notifier.py`，只用標準函式庫）。節流、每月額度保護與憑證設定見上方「Notify Bot 推播」。`notify_state.json` 已加入 `.gitignore`。
- **限制**：每月 200 則額度是整個官方帳號共用的，推播聊天室與你手動測試共用；警告與錯誤只推「標籤開頭」的 log（約定俗成的標記），沒有標籤的 log 不會推。

### [v2.5.0] - 2026-10-31
#### 遠端停止指令
- **新增**：`stop_command_chats` 名單內的好友（例如你自己的另一個帳號）傳來含 `stop_command`（預設「結束長輩圖機器人」，去除空白與標點後至少 4 字，否則改用預設值）的文字訊息，程式立即結束。訊息只要含指令全文就成立（例如「不要結束長輩圖機器人」也會停止）；對方連傳兩則以上時，讀最底部兩個訊息區塊。啟動時（或熱重載新增好友時）該好友已有的未讀訊息不算。停止時日誌印出「[遠端停止]」。結束碼為 3，`run_auto_reply.bat` 看到後直接關閉視窗。預設名單為空，等於不啟用。
- **運作方式**：LINE 視窗不提供訊息文字，所以改用截圖加 Windows OCR。只在該好友的視窗標題未讀數增加時才檢查，每個未讀數只檢查一次；檢查時會把該視窗切到前景、讀最底部左側（對方）的文字氣泡，讀完依 `close_window_after_send` 縮回去。只有一則新訊息時，照片、貼圖與自己送出的訊息一律略過；連傳兩則以上時逐一讀最底部兩個區塊（指令可能在貼圖之前）。已知限制：兩則氣泡間距小於約 6 px 時會被當成同一個區塊，第二個區塊可能是更早的舊訊息。OCR 對淺灰氣泡裡的小字不穩定，所以同一張截圖用 3 種前處理各讀一次，任何一次讀到指令就停止；3 次嘗試都讀不到字時不停止（Fail-Closed）。

- **內部整理**：左側訊息區塊切分抽成 `_left_message_blocks`，供文字或照片判斷與停止指令共用，判斷邏輯不變。

- **重名與重複開啟全量攔截**：合併精確與括號候選視窗並去重 HWND，即便一已讀一未讀，只要桌面存在超過 1 個同名視窗一律攔截拒發。
- **群組名稱關鍵字安全過濾**：為徹底防範將群組誤判為個人對話，名稱若包含「群組、聊天室、成員、專案、公務、同學、家族、group、team、club、project、family」等字樣，程式一律判定為群組並安全攔截（Fail-Closed 拒發）；若目標好友名稱包含上述關鍵字，建議於 LINE 中微調好友備註名稱。
- **零設定全自動頻道學習綁定 (Zero-Config Auto-Discovery & Auto-Binding)**：徹底廢除強制手動校準要求。單一監控對象或多對象視窗上線時，系統自動辨識底層快取頻道並動態完成映射持久化，完全開箱即用；同時原生支援現代電腦版 LINE 獨立視窗標題正常無未讀括號特性，消除等待括號卡死問題。
- **暫定綁定二次核驗 (Fail-Closed)**：自動學習的綁定先為暫定狀態，需經獨立傳入圖片核驗才轉為永久；核驗通過前一律不回覆，因此綁定後 6 秒內的後續圖片不會被回覆。目標視窗閒置且指紋已轉入其他訊息時自動撤銷錯綁。
- **跨版本快取目錄雜湊萃取相容**：同時相容 LINE 電腦版不同版本之單層與雙層 40 字元快取子目錄架構，確保監聽指紋精準鎖定目標對象。

#### 核心安全修復與深層防禦 (Critical Hardening & Architecture Upgrade)
- **多層深層防自循環架構 (Multi-Tier Self-Reply Defense)**：
  - **實體快取三元組差集快照**：發送前後自動對快取檔案進行路徑、修改時間（mtime）與檔案大小（size）全量差集快照，本機發送產生的新檔案或就地更新均自動記入黑名單。
  - **Windows DWM 像素實體位置方向核驗 (Fail-Closed)**：發送前核驗目標聊天室為前景視窗，透過 DWM 精準擴展客戶區邊界與動態 DPI 感知取樣，雙欄模式嚴密隔離側欄；最底部訊息若位於右側或無法判斷時一律安全攔截中止發送。
  - **跨重啟雙重持久化斷路器 (Circuit Breaker)**：同一對象 5 分鐘內最多回覆 2 次，超標啟動 30 分鐘退避鎖定；鎖定期、時間戳與 5 秒發送防抖保護全量持久化至 `circuit_breaker.json`，重啟常駐程式不失效。
  - **未讀視窗交叉驗證之頻道關聯**：底層媒體快取雜湊不盲目自動綁定單一好友，僅在該好友視窗出現實體未讀訊息時才安全關聯，徹底防止群組貼圖誤判。
  - **全方位多語系發送排除**：嚴格排除「您傳送了」、「You sent」、「写真を送信しました」等本機發送通知與文字。
- **全面支援 LINE 貼圖 (Sticker)**：
  - 關鍵字辨識庫擴充納入 `[貼圖]`、`[照片]`、`\b(photo|image|sticker)\b`。
  - 新增 `trigger_mode` 設定值 `"photo_and_sticker"`（同時支援長輩圖照片與 LINE 貼圖觸發）。

> **「凡由任一 AI 開發或修改完成之程式碼，必須第一時間主動送交給本機其他不同的 AI 開發工具進行獨立嚴格交叉審查（Cross-Review），徹底消除單一模型之認知盲點，收斂所有重大架構與安全性疑慮後方得視為交付。」**

#### 審查意見嚴重度分級與反覆修復流程 (Severity & Remediation Protocol)：
1. **意見分級規範**：審查工具（Reviewer）產出的審查意見必須嚴格分為三級：
   - **🔴 高度嚴重意見 (High / P1)**：邏輯無窮迴圈、誤傳至非目標對象、程式崩潰、未釋放資源、或核心安全漏洞。
   - **🟡 中度嚴重意見 (Medium / P2)**：邊界條件不嚴謹、可能遺漏事件、狀態持久化不同步、文件與實作矛盾。
   - **🟢 低度嚴重意見 (Low / P3)**：程式碼風格最佳化、註解潤飾、微小相容性建議、未追蹤檔案整理、非台灣用語等。
2. **高／中度嚴重意見強制循環修復 (Mandatory Re-Review Loop)**：
   - 被審查者（Developer）**必須強制全數修復所有高度（High）與中度（Medium）嚴重意見**。
   - 修復完成後，**必須再次送回原審查 AI 工具進行第二輪審查**。
   - 此送審 → 修復 → 覆審之循環流程**必須持續迭代，直至所有審查 AI 確認「無任何高度與中度嚴重意見」為止**。
3. **低度嚴重意見處置**：
   - 低度嚴重意見（Low / P3）由被審查者人工判斷是否修復。
   - 僅修復低度意見後，**不必再次送審**。

#### 執行標準作業程序：
1. **修補檔匯出**：程式碼撰寫完成並通過單元測試 (`python -m unittest discover -s tests`) 後，匯出最新 `git diff` 修補檔。
2. **三方獨立送審**：非本體的其餘三款 AI 工具各自啟動獨立工作階段進行審查：
   - `claude.cmd -p -` (Claude Code 深度程式碼審查)
   - `copilot.cmd -p ...` (GitHub Copilot 架構安全審查)
   - `codex.cmd exec` (OpenAI Codex 推理審查)
3. **台灣用語審查（每輪必含）**：審查報告必須獨立列出「台灣用語」一節，逐一檢查 README、程式註解、日誌訊息與測試說明，凡出現中國大陸慣用語（例如：進程、代碼、調用、運行、打開、優化、設置、窗口、激活、函數、閉環、死循環）一律列為低度意見，並提供台灣用語替換（行程、程式碼、呼叫、執行、開啟、最佳化、設定、視窗、啟用、函式、反覆修復、無窮迴圈）；若無則須明確寫「台灣用語：無問題」。
4. **版次號碼規則（語意化版本 主.次.修）**：
   - 主版：不相容改動（例如設定檔格式或指令改名，使舊設定失效）。
   - 次版：新增向下相容的功能。
   - 修訂：只修錯誤，不新增功能。
   每次改版須同步更新 `auto_reply.py`、`crawl_images.py` 的 `VERSION`、`run_auto_reply.bat` 標題、README 徽章、檔案結構中標有版次的註解與更新紀錄，並隨該次改版一併送審。
5. **報告存檔與反覆迭代**：各工具輸出之獨立審查報告存檔至本機，確認達成「零高、中度嚴重意見」之驗證標準。
